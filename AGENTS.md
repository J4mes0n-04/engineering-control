# Инструкции репозитория engineering-control

## Назначение

- Репозиторий хранит общую нормативную основу и версии контрактов PDE, ASE и QSRE.
- Рабочие проекты, Outcomes, реализация и доказательства конкретной поставки здесь не размещаются.
- Пока в `source-baseline.yaml` установлено `authoritative: false`, действующим источником нормативов остаётся PDE-репозиторий.

## Язык

- Человекочитаемые документы пишутся на русском языке.
- Имена файлов, каталогов, JSON/YAML-полей, версии и технические идентификаторы пишутся на английском языке.
- Английский термин при первом использовании сопровождается понятным русским пояснением, если его смысл не очевиден.

## Изменение нормативов

- Не изменяйте `governance/` автоматически.
- Каждое нормативное изменение оформляется отдельным Pull Request с причиной, влиянием, версией, changelog и назначенным approver.
- Изменение или удаление обязательного поля контракта требует major-версии.
- Не объединяйте перенос файла и изменение его смысла в одном коммите.
- OpenSpace может сформировать предложение, но не может самостоятельно изменить или утвердить нормативный документ.

## Границы

- Не добавляйте `workspaces/`, продуктовый код, secrets, production logs или персональные данные.
- Не копируйте PDE-specific rules, skills и локальную конфигурацию агентов без отдельного решения о совместимости.
- Сохраняйте происхождение snapshot через tag, полный commit SHA и список путей в `source-baseline.yaml`.
- Не объявляйте snapshot источником истины без отдельного cutover decision.

## Проверка

- Проверяйте синтаксис JSON/YAML и локальные Markdown links.
- Сверяйте неизменённые snapshot-файлы с источником по содержанию.
- До появления CI сохраняйте результаты проверки в описании Pull Request.
- Reusable workflows вызываются средами только по tag или полному SHA.
- Межрепозиторная автоматизация может создать Issue и не может объединять Pull Request, менять Pack или принимать Ready-решение.
